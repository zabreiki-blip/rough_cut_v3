# Первый проект: повторяемый пилот

Установите приложение по [основному README](../README.md), запишите выбранный
путь установки, ОС, архитектуру, версии Python, ffmpeg и браузера. Бесплатный
путь этого демо: готовые WAV + локальный ASR; платные ключи для него не нужны.
Не включайте облачный ASR или облачную озвучку при проверке бесплатного пути.

## Модель и кэш

Для короткого русского демо начните с локального faster-whisper `small` на CPU.
Для записи диктора задайте `SYNC_WHISPER_MODEL=small` в локальном `.env` перед
запуском сервера; для синхрона выберите Small в настройках локального распознавания.
Если обнаружение записи уже запустило сопоставление, дождитесь его окончания:
повторно нажимать кнопку сопоставления не требуется.
Первое использование скачивает модель при доступной сети, требует места и
может занять заметное время; фиксированное время холодного запуска не обещается.
Заранее убедитесь, что процесс приложения видит кэш именно своего профиля
(в локальном запуске по умолчанию `.cache/huggingface` в репозитории).
Кэш в `~/.cache/huggingface` другого запуска сам по себе этого не гарантирует.
После скачивания повторный запуск использует тёплый кэш. Отдельно запишите время
загрузки модели и распознавания, холодный это запуск или тёплый, название модели
и backend. Недоступная модель или ошибка скачивания — повод исправить окружение,
а не подтверждать пустые результаты. Для автономной проверки скачайте модель
до отключения сети; создание демо само ничего не скачивает.

## Путь в браузере

- [ ] В отдельной копии установите приложение по финальному README и запустите
  сервер. Сохраните команды, версии и любые ручные вмешательства без ключей.
- [ ] Выполните `./scripts/create-demo`, сохраните имя и URL проекта. Откройте
  главную страницу и этот проект. Команда кладёт сценарий в
  `ЗАГРУЗИТЬ/Сценарии`, просмотровку в `ЗАГРУЗИТЬ/Просмотровки`, диктора в
  `ЗАГРУЗИТЬ/Закадр`; фоновые задачи ещё не выполнены.
- [ ] Выберите `scenario.txt`. Проверьте три блока: ЗК, СНХ, ЗК. Тексты и
  спикер находятся в [expected.json](../examples/first-project/expected.json).
  Подтвердите сценарий самостоятельно.
- [ ] «Озвучка» → «Готовая запись»: обнаружьте `narrator.wav`, сопоставьте
  локально. Дождитесь окончания, прослушайте оба диапазона, проверьте полные
  начала/концы фраз и отсутствие пересечений. Подтвердите оба блока и примените
  запись к редакции. При изменении сценария сопоставление нужно повторить.
- [ ] Для `review.wav` выберите локальный ASR, дождитесь транскрипции и
  сопоставления СНХ. Проверьте источник, спикера и цитату «Сегодня мы открываем
  новый маршрут вдоль реки.». Прослушайте весь диапазон, при необходимости
  исправьте границы и подтвердите фрагменты, требующие проверки. Точное
  автосовпадение может сразу получить статус готового к сборке; повторной кнопки
  подтверждения для него нет. Цвет статуса не заменяет прослушивание исходника.
- [ ] Соберите актуальную редакцию и скачайте XML. Проверьте отсутствие
  ложного успеха после изменения сценария: устаревшая сборка должна требовать
  повторной сборки. Перезагрузите страницу и повторно откройте проект:
  выбранная редакция, подтверждения и готовность должны восстановиться.
- [ ] Ещё раз выполните helper: новое имя, первая копия и ручные правки целы.
  Результат ASR оценивайте по цитатам и слышимым границам, не побайтовым
  сравнением XML.

## XML в Premiere

Это импорт XML, не CEP conform. На текущем macOS Intel откройте XML в
установленном Premiere Pro 2025 и запишите полную версию приложения.

- [ ] В sequence три блока в порядке ЗК → СНХ → ЗК; нет пропавших медиа.
- [ ] Оба ЗК слышны целиком, СНХ содержит нужную цитату без обрезанных слов.
- [ ] Длительность sequence и каждого клипа соответствует слышимым диапазонам;
  запишите фактические значения, источник XML и расположение связанных WAV.
- [ ] Если Premiere недоступен, явно запишите «импорт не проверен».
  Apple Silicon, Docker и качество длинных реальных проектов требуют отдельных
  проверок и не считаются пройденными по результатам короткого демо.

## Дополнительный вариант: native macOS TTS

После прохождения готовой записи можно создать отдельный демо-проект и выбрать
native macOS TTS для ЗК. Нужен установленный русский системный голос; проверьте
его через `say -v '?'`. Голос и скорость меняют звучание и длительность,
поэтому заново прослушайте результат и пересоберите XML. Этот вариант не нужен
для основного демо и не заменяет проверку диапазонов готовой записи.

## Что сохранить в отчёте

Имя проекта, дата, версии, путь установки, холодный/тёплый кэш, модель/backend,
время каждого этапа, ручные правки, результат reload и открытия проекта,
путь XML, версия Premiere и слышимые границы. Непроверенное пометьте явно.
Проверки helper: `.venv/bin/python -m pytest tests/test_demo_project.py -q`.
Браузерный smoke и CI из `.github/workflows/ci.yml` запускаются отдельно;
прохождение двух тестов helper не означает успешный браузерный или XML-пилот.
