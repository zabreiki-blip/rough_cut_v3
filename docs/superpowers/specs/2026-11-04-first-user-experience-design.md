# Первое знакомство с Rough Cut: предлагаемые изменения

Дата: 2026-11-04. Статус: утверждено пользователем, начато выполнение плана.

## Цель и согласованный приоритет

Новый монтажёр самостоятельно проходит путь: создать проект → положить материалы
в `ЗАГРУЗИТЬ` → проверить сценарий → подготовить озвучку → найти и проверить
синхроны → скачать XML → импортировать его в Premiere.

Пользователь подтвердил: основной путь — браузер, папки `ЗАГРУЗИТЬ` и XML.
CEP остаётся дополнительным существующим способом; его развитие в эту работу
не входит. Папочная модель сохраняется как основной способ передачи материалов.

Основания: пользовательская проверка веб-интерфейса 2026-11-04 и приложенный
пользователем текст «Взгляд на rough_cut_v3 глазами стороннего пользователя».
Численные оценки и обещание запуска «за 5 минут» из текста не являются замерами.

## Рассмотренные подходы

1. Исправить только README. Быстро снимает вопросы с авторизацией, но сохраняет
   ручной путь к сценарию, противоречивые статусы и разрыв этапов.
2. Последовательно улучшить существующий веб-путь и установку. Переиспользует
   inbox API, редакции, фоновые задачи и XML; выбран пользователем.
3. Сделать новую оболочку с обязательной загрузкой файлов и переработать CEP.
   Требует новых механизмов, ослабляет удобную папочную модель и выходит за
   согласованный приоритет.

## Подтверждённые факты

- `scripts/setup-local` ставит dev/runtime, но не локальный ASR; токен при
  создании `.env` генерируется только при наличии `openssl`.
- `scripts/setup-macos-apple-silicon` ставит MLX в `.venv-macos-arm64`, но токен
  автоматически не генерирует. `doctor` по умолчанию проверяет `.venv`.
- Basic Auth описан в README в разделе API, а не возле первого открытия браузера.
- `GET /stage4/inbox` уже возвращает сценарии из новых и legacy-папок.
  Во вкладке редакций список фильтруется по ранее импортированным fingerprint;
  этот фильтр нельзя переносить в выбор исходника для нормализации.
- Загрузка сценария multipart не реализована. WAV/MP3 endpoint готового закадра
  не подходит для DOCX/TXT.
- В браузере после завершения TTS оставалась видимой кнопка остановки.
- При пустом mapping после успешного экспорта показывалось «Сначала соберите
  Stage 2 timeline». Пустой mapping не доказывает отсутствие таймлайна.
- `GET /stage3/status` уже разделяет обработку, сборку и готовность; веб-клиент
  пока не использует его как источник этих состояний.
- `docs/TECH_DEBT.md` фиксирует заморозку CEP. Подтверждённого полного пилота
  conform в Premiere в `docs/E2E_PILOT_CHECKLIST.md` нет.

## Предлагаемые решения

### Установка

Публичная пара для локальной установки — `scripts/setup-local` и
`scripts/run-local`. Основные локальные платформы: native macOS Apple Silicon
→ MLX и macOS Intel → faster-whisper. Для Linux и Windows/WSL2 основной
поддерживаемый маршрут — `scripts/bootstrap-docker`; существующий ручной
CPU-запуск не удаляется, но без отдельного пилота не объявляется проверенным.

Существующие команды и окружения сохраняются. Общая логика выбирает одинаковое
окружение для setup, run и doctor: явный `ROUGH_CUT_VENV` имеет приоритет,
для auto-профиля MLX используется `.venv-macos-arm64`, для CPU — `.venv`.
Специализированные native-команды продолжают выбирать MLX явно. Rosetta не
считается native ARM; неподходящий Python вызывает инструкцию, а не молчаливую
установку другого backend. Поддержка Python согласуется с текущей политикой:
3.11 — опорная версия, 3.12 — дополнительная для native Apple Silicon.
Явный `ROUGH_CUT_PROFILE` применяется ко всем трём командам через окружение
терминала; одноразовый override не считается постоянной настройкой. Если auto
выбирает новое окружение при наличии старого, runner объясняет выбор и команду
для явного старого профиля, не удаляет и не перемещает его.

Новый `.env` для native macOS получает локальный TTS; существующие непустые
настройки и токен не перезаписываются. Пустой/отсутствующий токен заполняется
через `secrets.token_hex(32)` выбранного Python, без зависимости от `openssl`.
Setup не устанавливает CEP и LaunchAgent; существующий `bootstrap-macos`
сохраняет явный расширенный сценарий и описывается отдельно.
При открытии браузера Basic Auth принимает произвольный логин и токен из
`ROUGH_CUT_API_TOKEN` в локальном `.env` как пароль. Setup выводит адрес и путь
к этому файлу с инструкцией, но не само значение токена.

### Материалы и редакции

Во вкладке «Нормализация» — список найденных сценариев, обновление списка,
объяснение папки `ЗАГРУЗИТЬ/Сценарии` и видимый выбранный файл. Ручной путь
остаётся в расширенных настройках. Пустой список не подставляет фиктивный файл.
Выбор не запускает разбор автоматически. Возврат в окно обновляет список без
сброса доступного выбранного файла; исчезновение файла требует нового выбора.

Первичный разбор использует существующий normalization job endpoint.
Новая редакция по-прежнему импортируется отдельным действием во вкладке
«Редакции». Смена файла при существующей разметке не может молча заменить её;
сохраняются проверки несохранённых правок, активной редакции и занятости проекта.
После reload восстанавливается исходник активной редакции, а не первый файл
из списка. Автоматическая активация импортированного черновика запрещена.

Прямая загрузка DOCX через браузер — отдельное последующее расширение, не
обязательное условие первой версии улучшений. Кнопка «Открыть папку» на сервере
не добавляется: Docker/удалённый backend не управляет Finder пользователя.

### Статусы и следующий шаг

Скрытые элементы действительно скрыты в браузере с загруженными стилями.
Состояния running/completed/cancelled/failed не оставляют лишних кнопок.
Готовность среды показывает доступные возможности: отсутствие облачного ключа
при рабочем локальном пути не превращает проект в «не готов».
Реальные недостающие зависимости и выбранная недоступная функция видимы.
При отсутствии ключа LLM по умолчанию выключен, с объяснением ограничений.

Для сборки отдельно показываются задача, актуальность результата и пропуски.
Источником служит `/stage3/status`; поля и смысл backend-контракта сохраняются.
Legacy XML без build_id обозначается как экспортированный файл, а не как
подтверждённая актуальная сборка без пропусков. Смена редакции/озвучки/совпадений
обновляет готовность. Доступность следующей кнопки не рассчитывается второй
независимой системой поверх существующих guards.

Основные действия и состояния называются по-русски; TTS/Whisper/API остаются
в подробностях. На каждом этапе виден следующий шаг. После XML — инструкция
импорта в Premiere и различие черновика с заглушками и сборки без пропусков.
В карточке проекта и title нет общего ярлыка `Stage 1` для всего проекта.

### Документация и демо

README — короткий маршрут пользователя: назначение, материалы, выбор запуска,
авторизация, три папки `Сценарии`/`Просмотровки`/`Закадр`, работа до XML.
API, переменные среды, deployment и contributor-инструкции получают отдельные
документы. Ссылки и тесты документационных контрактов обновляются вместе.
Расположение раздела не меняет статус старых API и не удаляет CEP.

Демо: три блока (два закадра и один синхрон), небольшой собственный текст,
готовая запись диктора и короткая WAV-просмотровка в `examples/first-project`.
`scripts/create-demo` копирует исходники в новый уникальный проект, не меняет
другие проекты и не запускает облачные услуги. Основной демонстрационный путь
использует готовую запись и локальный ASR, поэтому не требует macOS `say` внутри
Docker. Дополнительно описывается native macOS TTS.
Результаты распознавания не подменяются заранее подтверждёнными ответами.
Первое скачивание модели и повтор с кэшем описываются раздельно.

## Границы

Не менять алгоритмы matching/retiming, формат редакций и UID, хранение озвучки,
правила платных запусков, блокировки и бюджеты. Не выполнять массовые миграции
проектов и не модернизировать CEP. Не менять Python/пины зависимостей вне
текущей политики; если обновление необходимо — отдельная обоснованная задача.

## Критерий успеха

Новый пользователь по README создаёт отдельный демо-проект, выбирает сценарий
без набора пути, проверяет блоки, применяет готовую запись, проверяет синхрон,
скачивает XML и импортирует его в Premiere. Без платных ключей и участия автора.
На каждом этапе видны состояние, причина блокировки и следующее действие.
Прогон фиксирует платформу, backend, версии, холодный/тёплый запуск и реальные
ограничения; наличие файла XML не заменяет проверку импорта и воспроизведения.
Первая обязательная конфигурация пилота — текущий macOS Intel/x86_64 с
установленным Premiere Pro 2025; точные версии приложения и ОС записываются
перед запуском. Apple Silicon и Linux/Docker проверяются отдельно, их статус
не выводится из успешного Intel-прогона. Windows-пилот — последующее расширение.

## Что оставлено исполнителю

Точное расположение подсказок и полей, имена внутренних функций, компактность
карточек, формат синтетического аудио и минимальный браузерный тестовый инструмент.
Выбор не должен добавлять продуктовый framework или переписывать рабочие модули.
