# Закадр диапазонами из общей записи

Статус: проект решения для планирования; реализация не начата.

## Требование пользователя

Поддержать чистовой закадр, начитанный одним диктором в порядке сценария.
Основной случай — один сплошной файл записи («одной колбасой»), иногда с дублями
(одна фраза начитана подряд несколько раз с разными ударениями). Вторичный случай —
несколько файлов, части одной записи.
Каждый блок должен брать свой отрезок общего файла. Отдельные `zkN.wav`
для этой записи не создавать. Решение по каждому блоку ЗК смешанное: если у блока
есть подтвержденный диапазон записи диктора — в монтаж идет он; иначе — TTS (если WAV TTS есть),
иначе блок «нет озвучки». Публикация по блокам: частичная запись допустима (диктор начитал
не все блоки, блоки переписаны после записи). Текущая задача — только план работ.

## Предлагаемая архитектура

Во вкладке «Озвучка» добавить источник «Готовая запись». Импортировать WAV/MP3
в неизменяемое хранилище проекта по хешу содержимого. WAV использовать напрямую;
MP3 один раз декодировать в общий PCM WAV. Копия для ASR допустима, нарезанные
монтажные файлы по блокам не создаются. Сохранить исходник и происхождение копий.

Автоопределение: файл в `ЗАГРУЗИТЬ/Закадр/` (и файл, пришедший через inbox) автоматически
регистрируется как источник записи и ставит в очередь сопоставление. Запускается только
локальный ASR; автопереход на платный backend не выполняется. Если записи нет — поведение как сейчас (TTS).

Несколько файлов (вторичный случай) — части одной записи. Части сортируются по имени и выравниваются
последовательно по оставшимся активным блокам ЗК; подтвержденные диапазоны частей не пересекаются.
Дубли — см. раздел «Дубли» ниже.

Существующий ASR дает слова с таймкодами. Отдельный алгоритм последовательно
сопоставляет их только с активными блоками `voiceover`, исключая поглощенные
блоки и другие типы. Использовать ожидаемый произносимый текст сценария, сохраняя
исходный текст для отображения. Совпадения — предложения границ, требующие
подтверждения пользователя перед публикацией. При пропусках или неоднозначности
показывать проблему, сохраняя найденные последующие опоры.

Единица привязки: `block_uid`, хеш произносимого текста, идентификатор записи,
хеш медиа, полная длительность, `source_in_sec`, `source_out_sec`, границы речи,
статус и происхождение решения. Время — секунды от начала монтажного WAV.
Связь со сценарием включает `scenario_revision_id` и версию нормализации.

Таймлайн и оба XML-экспортера используют общий путь и диапазон. Длительность
монтажного блока равна длине диапазона, длительность XML media — всей записи.
Запись остается на дорожке закадра: TTS-клипы (`in=0`) и диапазоны общей записи могут
идти на одной дорожке вперемешку. TTS продолжает использовать отдельные WAV.
Новые поля имеют значения по умолчанию для старых проектов.

Смешанный режим по блокам: `voice_source = recorded | tts | none` с происхождением `auto`
или `manual`. Ручной выбор «использовать TTS для этого блока» действует поверх найденного
диапазона. Таймлайн и build учитывают `voice_source` каждого блока.

## Рассмотренные подходы

- Нарезка в `zkN.wav`: меньше изменений экспорта, но не соответствует выбранному пользователем способу.
- Общий файл с диапазонами: выбран пользователем; требует изменений моделей,
  проверки готовности, версий и обоих экспортеров.
- Диктор отдельной дорожкой рядом с TTS: отклонен; лишняя работа монтажеру
  (два источника закадра вместо одного решения по блоку).

## Дубли

Основной сценарий — один сплошной файл, в котором дубли встречаются как повторные прочтения.
Дубли не считаются пропусками или ошибками выравнивания.

- Дубль всего блока: последовательное выравнивание распознает повторные прочтения текста блока
  подряд и не сдвигает из-за них следующие блоки. Все дубли сохраняются как кандидаты блока
  (`takes`: список диапазонов с уверенностью). По умолчанию выбирается ПОСЛЕДНИЙ полный дубль
  (конвенция «последний — правильный»). Блок получает пометку «дубли: N» и статус `needs_review`
  до подтверждения. Пользователь может прослушать каждый дубль и выбрать другой; выбор
  сохраняется как ручное решение (`selected_take`).
- Частичный дубль (переговорено слово или фраза внутри блока): MVP — один диапазон на блок.
  Блок помечается «частичный дубль», предлагается диапазон, исключающий неудачный кусок,
  если это возможно без вырезания из середины; иначе — весь отрезок от начала первого прочтения
  до конца последнего с пометкой. Решение за пользователем. Склейка блока из нескольких отрезков
  одной записи — пункт «после MVP».
- Повтор фразы, которая в сценарии встречается дважды в разных блоках, не является дублем:
  отличается от дубля по соседству и порядку.

## Ограничения и приемка

- MVP: одна чистовая запись (основной случай — один файл; вторичный — несколько частей), один диктор,
  порядок сценария; дубли — по правилам раздела «Дубли».
- Никакой нарезки по блокам, изменения темпа и автоматического удаления дыхания.
- Начальные границы определяются по словам; ручная коррекция доступна. Без
  паузы между словами ASR не гарантирует точный монтажный стык.
- Диапазоны конечны: `0 <= in < out <= media_duration`; подтвержденные интервалы
  первой привязки идут в порядке записи без пересечения. Перестановка неизменных
  блоков в следующей редакции может менять порядок воспроизведения диапазонов.
- До применения готовой разметки текущая озвучка не меняется. Публикация идет по блокам:
  блок с подтвержденным диапазоном получает запись, остальные сохраняют TTS или «нет озвучки».
  Частичная публикация допустима (диктор начитал не все, блоки переписаны после записи).
- Переключение редакций восстанавливает собственные привязки. Изменение текста
  инвалидирует соответствующий диапазон; неизменные и перемещенные блоки переиспользуются.
- Правка диапазонов инвалидирует таймлайн и Stage 3 build; смена записи инвалидирует ее ASR-кеш.
- Правка решения по блоку (`voice_source`, ручной override TTS) инвалидирует таймлайн и Stage 3 build.
- Смешение TTS и записи на одной дорожке ЗК допустимо. Возможна разница громкости TTS и диктора:
  предупреждение в UI; нормализация громкости вне MVP.
- На двух блоках одного WAV экспорт содержит разные `in/out`, полную длительность
  исходника и уникальные ID клипов. Старый путь TTS работает по-прежнему.

## Оставлено исполнителю

Конкретная функция оценки уверенности и оптимизация последовательного выравнивания.
Новые ASR-модели и зависимости не требуются для исходного решения; выбор новой
библиотеки при реализации потребует отдельного обоснования и проверки политики зависимостей.
