# Общий план устранения проблем трёх проектов

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Получить достоверный статус и проверенную сборку UIP_ATOM_001, BRIK и SPAS_DM_1s_001.

**Architecture:** Сначала воспроизвести расхождения между файловой системой, отчётами задач и планами сборки. Исправлять общую логику после подтверждения причины, затем закрыть монтажные задачи каждого проекта и проверить новые сборки.

**Tech Stack:** Существующий Python/Flask backend, JSON-артефакты, Docker/macOS, XML для Premiere, CEP-панель.

**Spec:** Запрос пользователя «сделай общий план работ» и аудит трёх проектов в текущем диалоге. Это общий план; точные изменения интерфейсов и тестов определяются после диагностики.

## Global Constraints

- Сохранять исходные медиа, записи диктора, редакции сценариев и существующие сборки.
- Не запускать повторно платные TTS/ASR/LLM операции ради обновления диагностики.
- Отделять успешное выполнение задачи, доступность медиа и готовность монтажа.
- Не считать отсутствие файла в одном окружении доказательством потери исходника.
- Монтажный выбор дублей и лайфов проверять по содержанию; автоматическое сопоставление не заменяет редакторское решение.

## Review Focus

- Один файл доступен на macOS, но недоступен по тому же абсолютному пути в контейнере.
- Старый отчёт задачи относится к другой редакции или более раннему состоянию проекта.
- XML создаётся при отсутствии зарегистрированных источников или наличии заглушек.
- Сопоставленный синхрон содержит наложение речи или речь за границами выбранного отрезка.
- Исправление путей нарушает импорт XML в Premiere на хосте.

## 1. Зафиксировать и воспроизвести исходное состояние

- [ ] Сохранить диагностический снимок активных редакций, последних отчётов, планов и идентификаторов сборок без перезаписи рабочих данных.
- [ ] Для каждого проекта составить перечень реальных пропусков, спорных синхронов и сообщений о недоступных файлах.
- [ ] Проверить доступность одинаковых медиа в среде backend и на macOS; сопоставить отчёты с редакциями и временем создания.

**Готово, когда:** для каждой проблемы указано, воспроизводится ли она сейчас, к какой редакции относится и на каком этапе возникает. Статус BRIK с 350 блокировками не принимается за актуальную потерю медиа: 339 указанных файлов при аудите доступны локально.

## 2. Устранить подтверждённые проблемы путей и регистрации источников

- [ ] Проверить границу между путями для чтения backend и путями, записываемыми в XML для Premiere; определить причину расхождения до изменения кода.
- [ ] Исправить подтверждённые ошибки разрешения путей и проверки наличия файлов в соответствующем окружении.
- [ ] Разобрать нулевой каталог источников SPAS: проверить входные папки, обнаружение файлов и регистрацию медиа.
- [ ] Проверить регрессии на существующих файлах, отсутствующем файле, кириллических именах и импорте XML на macOS.

**Готово, когда:** доступные исходники корректно обнаруживаются backend, реальное отсутствие файла объясняется точно, Premiere получает доступные ему пути.

## 3. Сделать состояние проекта достоверным

- [ ] Проверить, как отчёты задач связаны с активной редакцией, планом и сборкой; определить причину расхождений.
- [ ] Разделить в API и интерфейсе завершение обработки, черновую сборку и сборку без пропусков.
- [ ] Показывать реальные незакрытые задачи и явно обозначать устаревшие результаты.
- [ ] Проверить случаи нулевого каталога источников, заглушек и переключения редакции после сборки.

**Готово, когда:** пользователь видит актуальную готовность и конкретные оставшиеся действия; создание XML само по себе не обозначает готовый монтаж.

## 4. Закрыть монтажные задачи проектов

- [ ] UIP_ATOM_001: назначить и проверить 5 вставок ведущего вместо 50 секунд заглушек.
- [ ] BRIK: назначить 7 лайфов вместо 70 секунд заглушек, проверить наложение речи в snh95 и snh96.
- [ ] BRIK: повторно проверить snh122 и snh178, отмеченные старым отчётом как речь за границами отрезка; подтвердить актуальность перед исправлением.
- [ ] SPAS_DM_1s_001: после восстановления каталога выполнить сопоставление 121 синхрона и разобрать 28 лайфов; подтвердить наличие необходимых материалов.

**Готово, когда:** обязательные фрагменты назначены и проверены либо по каждому отсутствующему материалу записана конкретная внешняя зависимость. Фиктивные назначения для снятия блокировки недопустимы.

## 5. Проверить новые сборки

- [ ] Запустить релевантные проверки изменённой логики путей, статусов и сборки.
- [ ] Создать отдельную новую сборку для каждой активной редакции, не перезаписывая предыдущие результаты.
- [ ] Сверить число обязательных сегментов, заглушки, границы речи, длительность, источники и блокировки.
- [ ] Импортировать XML в Premiere в тестовую последовательность; проверить offline media, спорные стыки и назначенные вручную фрагменты.

**Готово, когда:** все обязательные элементы присутствуют, нет необъяснённых блокировок, пути работают в Premiere, проблемные стыки проверены на слух и по изображению. Если Premiere недоступен, проверка импорта остаётся открытой.

## 6. Закрепить результат

- [ ] Документировать поддерживаемое сопоставление путей и значение статусов готовности.
- [ ] Сохранить итоговый отчёт по трём проектам: редакция, сборка, проверки, оставшиеся зависимости.

**Готово, когда:** состояние каждого проекта можно понять из одного актуального отчёта и повторить проверку без ручного сравнения нескольких JSON-файлов.

## Порядок и зависимости

Диагностика → пути и источники → статусы → закрытие монтажных задач → контрольные сборки → документация.

После общей технической проверки проекты можно обрабатывать независимо. Предварительный порядок: UIP_ATOM_001, BRIK, SPAS_DM_1s_001 — по объёму известных незакрытых задач; сроки выпуска могут изменить этот порядок.
