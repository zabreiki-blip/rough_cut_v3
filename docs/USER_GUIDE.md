## Простая загрузка файлов

После создания проекта приложение автоматически создаёт три пользовательские
папки:

```text
projects/<project>/ЗАГРУЗИТЬ/Сценарии/
projects/<project>/ЗАГРУЗИТЬ/Просмотровки/
projects/<project>/ЗАГРУЗИТЬ/Закадр/
```

- в `Сценарии` кладутся `.doc`, `.docx`, `.txt` или `.md`;
- в `Просмотровки` кладутся видео и отдельные `.wav`/`.mp3`;
- в `Закадр` кладутся записи закадрового голоса для локального сопоставления;
- видео и отдельный звук с одинаковым именем связываются автоматически;
- старые `input/` и `media/reviews/` продолжают поддерживаться.

### Версии сценария

История работает одинаково для любого проекта из `projects/`; имя проекта не
зашито в механизм версий. Рабочий цикл во вкладке «Редакции»:

1. Создай, проверь и сохрани исходную нормализацию. При первом импорте она
   автоматически фиксируется как baseline `rev_0001`.
2. Положи новый `.doc`, `.docx`, `.txt` или `.md` в
   `ЗАГРУЗИТЬ/Сценарии`, выбери его и нажми «Загрузить новую редакцию».
3. Приложение создаст следующий уникальный `rev_NNNN`, сравнит его с активной
   редакцией и сохранит как отдельный черновик. Импорт сам по себе не меняет
   активную редакцию.
4. Проверь diff и нажми «Открыть» у нужной редакции. Несохранённые правки
   нормализации интерфейс сначала предложит сохранить. После переключения
   редакцию нужно проверить и подтвердить перед TTS, Stage 2 и Stage 3.

Каждая редакция хранит собственные снимки исходного файла, нормализации,
подготовленного сценария и карты озвучки; при наличии также сохраняются sync
matches и таймлайн. Озвучка привязана к стабильному UID блока: `zk1`, `zk2`, …
остаются позиционными экспортными именами, поэтому WAV неизменившихся или
перемещённых блоков можно переиспользовать между редакциями.

Перед импортом и переключением API сверяет `work/active_revision.json` с
`scenario_revision_id` рабочей нормализации. Если они расходятся, операции
блокируются, а вкладка предлагает «Восстановить». Восстановление сначала
сохраняет текущее состояние в `versions/recovery/<timestamp>/`, затем разворачивает
выбранную известную редакцию. Не редактируй файлы в `versions/` вручную.

Импорт, переключение и восстановление также блокируются, пока в этом же проекте
активна нормализация, TTS, sync или подготовка Stage 3. Задачи других проектов
могут выполняться независимо.

## Подготовка короткого сценария

Рекомендуется `.docx` или `.txt`. `.md` также поддерживается; старый `.doc`
требует `catdoc` или `antiword`. Один смысловой блок отделяйте пустой строкой,
явно указывайте тип. Пример из [демо](../examples/first-project/scenario.txt):

```text
ЗК1: У реки появился новый прогулочный маршрут.

СНХ Анна Миронова, координатор проекта — review.wav 00:00:00 — Сегодня мы открываем новый маршрут вдоль реки.

ЗК2: Первые посетители уже вышли на набережную.
```

ЗК — закадровый текст; СНХ — реплика в исходном звуке. Имя, файл и таймкод
помогают найти синхрон. Не отправляйте реплики спикеров в закадр. Для закадра
поддержаны также `ЗК:`, `VO:`, `NARRATOR:`, `ЗАКАДР:` и `[[VO]]…[[/VO]]`.
Разметка и форматирование Word описаны в [Stage 1](STAGE1_GUIDE.md#1-подготовка-сценария).

Просмотровки: `.3gp`, `.avi`, `.m2ts`, `.m4v`, `.mkv`, `.mov`, `.mp4`,
`.mpeg`, `.mpg`, `.mts`, `.mxf`, `.webm`; отдельный звук — `.wav`, `.mp3`.
Готовый закадр — `.wav` или `.mp3`. Поддерживаемое расширение не гарантирует
чтение любого кодека: проблемный файл проверьте через ffmpeg/ffprobe.

## Первый разбор

1. Откройте проект, выберите первый сценарий и запустите разбор. Локальный
   разбор без LLM не требует ключей провайдера.
2. Проверьте текст и тип каждого блока: закадр, синхрон, ведущий, лайф или
   технический блок. Исправьте ошибки и подтвердите сценарий.
3. После появления активной редакции её исходный файл закреплён. Выбор другого
   исходника для повторного первичного разбора заблокирован: используйте
   «Редакции» → «Загрузить новую редакцию». Проверять и править блоки текущей
   редакции можно в нормализации.

## Озвучка

Выберите один из двух путей на вкладке «Озвучка».

- **Готовая запись**: положите запись в `ЗАГРУЗИТЬ/Закадр`, сопоставьте локально,
  прослушайте диапазоны каждого блока, поправьте границы, подтвердите и нажмите
  «Применить запись к редакции». Распознавание использует установленный ASR;
  при первом запуске модель скачивается. При дублях можно выбрать нужный.
- **Синтез речи**: нажмите «Создать озвучку». На нативном macOS бесплатный
  `macos` использует системный `say`; в Docker нужен macOS Connector.
  Облачный провайдер требует собственного ключа и может быть платным.

«Проверить аудиофайлы» проверяет готовность озвучки. `--dry-run` в CLI
создаёт заглушки без речи и не заменяет прослушивание. Можно смешивать запись
и TTS для разных блоков; проверьте громкость и тембр. Подробности —
[готовая запись](STAGE1_GUIDE.md#готовая-запись-диктора).

## Синхроны и сборка

1. Найдите файлы из `ЗАГРУЗИТЬ/Просмотровки` и запустите локальное распознавание
   синхронов. CPU использует faster-whisper, нативный Apple Silicon — MLX.
2. Дождитесь завершения. Прослушайте найденные реплики, особенно сомнительные,
   проверьте спикера и source in/out; при необходимости выберите альтернативу
   и подтвердите. Не найденные/не подтверждённые фрагменты могут остаться
   плейсхолдерами. Повтор одного фрагмента в нескольких местах допустим.
3. Нажмите «Собрать таймлайн», проверьте сводку, затем «Скачать XML для Premiere».
4. В Premiere Pro импортируйте XML, проверьте доступность исходников, порядок
   ЗК/СНХ, звук и границы. Сверьте результат с
   [чеклистом](FIRST_PROJECT_CHECKLIST.md). XML — файл монтажа, не готовый видеоролик.

Фактический импорт текущего демо в Premiere пока не проверен; наличие XML
не подтверждает корректный импорт. CEP для этого браузерного пути не требуется.
Панель [CEP](../cep/README.md) заморожена и доступна как дополнительная интеграция.

## Демо и первый холодный запуск

`./scripts/create-demo` создаёт отдельный проект `demo_<suffix>` из
[examples/first-project](../examples/first-project/README.md). В комплекте сценарий,
запись закадра и синтетическая просмотровка; подготовка не запускает ASR,
сеть или платные сервисы. Для демо используйте готовую запись и локальный ASR.
Модель Whisper не включена: первое распознавание требует сети и свободного
места (medium около 1.5 ГБ). Фиксированного времени холодного запуска нет.
Native macOS TTS — дополнительный вариант, готовые WAV позволяют пройти демо
и на других поддерживаемых системах.
