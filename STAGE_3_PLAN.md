# Stage 3 — headless-монтаж по просмотровкам

## Цель

Собрать готовый редакционный таймлайн из отрендеренных просмотровок внутри
Docker. Premiere Pro на этом этапе не запускается: он нужен только для импорта
готового XML и последующей замены proxy на исходные sync-sequences.

## Каталог проекта

Просмотровки каждого проекта лежат в фиксированном каталоге:

```text
projects/<project>/media/reviews/
```

Docker уже получает `projects` через существующий bind mount. Внешний каталог
или дополнительный доступ к `/Volumes` не требуются. Вкладка «Сборка» сканирует
папку автоматически при первом открытии и показывает найденные видео, WAV и MP3.

Для ускорения Whisper можно положить рядом с просмотровкой одноимённый WAV или
MP3: `Курская.mp4` + `Курская.wav`. Они считаются одним логическим источником:
аудиофайл используется для распознавания, а MP4 — для изображения и экспорта
XML. Если есть только MP4, аудио по-прежнему читается прямо из него. Если есть
только WAV/MP3, распознавание и сопоставление работают, но UI помечает источник
как ожидающий видео; аудиофайл не попадает в видеобины XML.

Полный скелет создаётся при инициализации каждого проекта:

```text
media/{reviews,archive,films,photos,graphics}
versions/{scenarios,diffs,timelines}
```

## Рабочий поток

1. Пользователь копирует отрендеренные просмотровки в `media/reviews` проекта.
2. Backend запускает `ffprobe`, сохраняет стабильные IDs/fingerprints и
   показывает длительность, fps, размер кадра и файла.
3. Аудио просмотровок индексируется существующим Whisper/matcher.
   Безымянный блок `СНХ` наследует спикера последнего явно подписанного
   синхрона, но его фраза ищется независимо по всему транскрипту этой
   просмотровки. Поэтому монтаж может вырезать середину, менять куски местами
   и брать следующую фразу из другого места интервью.
4. Подтверждённые ranges собираются в XMEML v5:
   - bin `RC_VIEWINGS`;
   - одна полная sequence `RC_SRC_<имя>` на каждую просмотровку;
   - финальная sequence `ROUGH_CUT_<project>` из nested ranges `RC_SRC_*`;
   - ЗК WAV и placeholders для отсутствующих источников.
5. При необходимости Docker отдельно рендерит контрольный preview через ffmpeg.
6. Пользователь импортирует XML в Premiere и заменяет полный proxy-клип внутри
   каждой `RC_SRC_*` исходной sequence с тем же нулём и fps.

Одна `RC_SRC_*` создаётся на одну просмотровку, а не на каждый СНХ.

## Безопасность и проверка

- Scan жёстко ограничен `projects/<project>/media/reviews` и не следует по
  symlink за пределы проекта.
- Исходные просмотровки не изменяются.
- Повторное сканирование сохраняет Source ID; изменение файла меняет fingerprint.
- Неоднозначное сопоставление просмотровки и Stage 2 source не выбирается молча.
- Перед заменой proxy проверяются fps, нулевая точка и доступная длительность.
- XML содержит host-пути к project media, а не контейнерные `/app/...` пути.

## BRIK pilot

Девять MP4 скопированы в `projects/BRIK/media/reviews` (H.264, 854×480,
25 fps). Первый пилот проверяет автоматическое сканирование, mapping по именам,
nested XML и замену одной `RC_SRC_*` в Premiere. Смольникова имеет заметное
расхождение полной длительности с ранее зарегистрированной sync-sequence,
поэтому для неё отдельно проверяются source ranges.
