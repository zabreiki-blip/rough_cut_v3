# Технический аудит rough_cut_v3

Дата: 2026-06-09
Объект: текущее рабочее дерево `master`, включая незакоммиченные изменения
Объем: работающий функционал, надежность Stage 1/Stage 2, Docker, тесты и эксплуатация

Допущение: проект используется локально одним владельцем в доверенной сети. Аутентификация API, защита от внешних пользователей и хранение локальных секретов не считаются блокерами.

## Резюме

Проект имеет понятное модульное разделение и рабочую базовую архитектуру, но сейчас основной pipeline работает нестабильно и требует ручного контроля.

Главные риски:

1. `dry_run` перезаписывает существующие реальные WAV-файлы тишиной.
2. Контракт ID между Stage 1 и Stage 2 нарушен, из-за чего WAV не попадают в timeline/XML.
3. Поврежденный WAV проходит валидацию и попадает в manifest.
4. Измененный текст или настройки TTS не приводят к обновлению существующего WAV.

Итоговая оценка: **требуются P0/P1-исправления, чтобы pipeline Stage 1 → TTS → Stage 2 работал предсказуемо**.

## Критические проблемы

### Исправлено. Анализ без ручных маркеров падал

Файл: `src/stage1/analyzer.py:647-650`

После fallback, LLM или форматного анализа код обращается к `block.text`, но у `NarrationBlock` есть только `text_original` и `text_for_tts`.

```python
for block in blocks:
    text = block.text.strip()
```

Воспроизведение на обычном `.txt` без ручных маркеров:

```text
AttributeError: 'NarrationBlock' object has no attribute 'text'
```

Ручные маркеры скрывают проблему, потому что для `extraction_method == "manual_markers"` эта ветка не выполняется.

Риск: основной fallback/LLM/docx-formatting workflow завершается ошибкой после уже выполненного анализа.

Статус: исправлено обращение к полям `text_original`/`text_for_tts`; добавлены regression-тесты успешной LLM-ветки и fallback. Реальный запрос OpenRouter прошел успешно. Для Stage 2 по-прежнему лучше отказаться от best-effort замены строк в исходном тексте и формировать структурированный timeline из подготовленных блоков.

### Исправлено. Dry-run уничтожал существующее аудио

Файл: `src/stage1/gemini_tts.py:587`

Добавлена проверка `_is_valid_wav(out_file)` перед записью тишины в dry-run режиме. Если файл уже валиден — он пропускается (попадает в `skipped`), тишина не пишется. Regression-тест добавлен: `tests/test_p0_p1_regressions.py::DryRunPreservesExistingWavTest`.

## Высокий приоритет

### Исправлено. Stage 1 и Stage 2 использовали несовместимые ID

Файлы:

- `src/stage1/analyzer.py:632-650`
- `src/stage2/timeline_parser.py:89-115`

Stage 1 всегда перенумеровывает блоки в `zk1..zkN`, но для ручных маркеров сохраняет исходный raw-текст. Stage 2 использует номер из исходной метки.

Подтвержденный пример:

```text
Исходная метка:       ЗК10
Prepared/TTS ID:      zk1
Timeline ID:          zk10
```

Дополнительные ошибки парсера:

- `ЗК1` + ненумерованный `ЗК` дают два сегмента `zk1`;
- `ЗК4.1` превращается в ID `zk4`, а `.1` попадает в текст;
- после объединения блоков Stage 1 строковая вставка маркеров ненадежна.

Статус: исправлено.
- `timeline_parser.py:93-97` — ZK-сегменты теперь всегда нумеруются последовательным счётчиком, номер из исходного маркера игнорируется. Устраняет mismatch `ЗК10 → zk10 vs zk1`, дубли `zk1` от смешанных маркеров и суффиксы типа `ЗК4.1`.
- `analyzer.py:643-652` — raw_text для всех не-manual стратегий теперь получает канонические номера (`ЗК1:`, `ЗК2:`, ...) вместо безымянного `ЗК:`.
- Тесты: `tests/test_stage2_timeline_parser.py` (5 тестов).

### Исправлено. Поврежденный WAV проходил валидацию

Файл: `src/stage1/validator.py:143`

Заменён `warnings.append` на `errors.append` для случая `duration_ms == 0`. Теперь нечитаемый WAV даёт `ok=False` и блокирует запись manifest. Regression-тест добавлен: `tests/test_p0_p1_regressions.py::CorruptedWavFailsValidationTest`.

### Исправлено. Валидный, но устаревший WAV всегда пропускался

Файл: `src/stage1/gemini_tts.py`

Добавлен fingerprint-механизм (`SHA-256` от `text + provider + voice + gender + speed`):
- Sidecar-файл `zkN.wav.meta` пишется после каждого успешного синтеза.
- Skip-условие: `_is_valid_wav(out_file) AND fingerprint совпадает`.
- Нет `.meta` файла или fingerprint изменился → WAV регенерируется.
- Dry-run не пишет fingerprint (silence ≠ реальный синтез).
- Тесты: `tests/test_p0_p1_regressions.py::StaleWavRegenerationTest` (5 тестов).

## Средний приоритет

### Исправлено. Нет изоляции путей между проектами

Файл: `src/api.py:132-141`

`_abs_path()` получил параметр `root` (по умолчанию `PROJECTS_DIR`). Все вызовы обновлены — передают `paths["root"]` = `projects/<project>/`. Теперь пути за пределами каталога текущего проекта отклоняются с ошибкой 400.

### Исправлено. Неограниченные фоновые TTS-задачи

Файл: `src/api.py`

Добавлен `threading.Semaphore(_TTS_CONCURRENT_MAX=3)`. Каждый worker захватывает семафор перед синтезом и освобождает в `finally`. Не более 3 параллельных TTS-синтезов; остальные задачи ждут в очереди потоков.

### Исправлено. XML описывал аудио не так, как оно генерируется

Файл: `src/stage2/xml_export.py`

Добавлена функция `_wav_audio_params()` — читает реальные `sample_rate`, `bit_depth`, `channels` из каждого WAV через `wave`. При ошибке чтения возвращает TTS-defaults (24000 Hz / 16-bit / mono). XML-метаданные теперь соответствуют фактическому файлу.

### Исправлено. Ошибки placeholder подавлялись

Файл: `src/api.py:697-715`

При ошибке генерации PNG теперь: (1) добавляется запись в `warnings` ответа; (2) `seg.placeholder_path` обнуляется, чтобы XML не ссылался на несуществующий файл.
