# Аудит проекта rough_cut_v3 — Отчет

## Общая характеристика
**rough_cut_v3** — это Python-приложение для автоматизации подготовки закадровой озвучки видео. Проект реализует первый этап pipeline: анализ сценария → разбиение на блоки → синтез TTS → валидация и манифест для сборки в Premiere.

**Технологический стек:**
- Python 3.11
- Flask (веб-интерфейс)
- Google Gemini TTS, OpenRouter TTS, macOS `say` (движки озвучки)
- python-docx (парсинг .docx)
- catdoc (парсинг .doc)
- Docker + Docker Compose
- HTML/CSS/JS (фронтенд)

## Сильные стороны

### 1. Архитектура и дизайн
- **Четкое разделение ответственности:** CLI, API, движки TTS, валидатор, анализатор — каждый в своем модуле.
- **Гибкость провайдеров TTS:** Поддержка Gemini, OpenRouter, macOS `say` с возможностью переключения через переменные окружения.
- **Docker-дружелюбность:** Dockerfile и docker-compose.yml позволяют запускать backend в контейнере, включая поддержку macOS-коннектора.
- **API-первый подход:** REST-эндпоинты для всех операций, что упрощает интеграцию.

### 2. Функциональность
- **Разумная автоматизация:** Использование LLM (OpenRouter) для анализа сценария и выделения закадрового текста.
- **Ручные метки:** Поддержка ручной разметки через заливку в Word, теги `[[VO]]`, префиксы `ЗК:`, `NARRATOR:`.
- **Фильтрация:** Автоматическое исключение спикерских реплик (`СПИКЕР:`, `СНХ:`, `ВЕДУЩИЙ:`) и технических меток (`ВОТ ССЫЛКА`, `ВИДЕО`, `ЛАЙФ`, `ВНИМАНИЕ`).
- **Dry-run режим:** Возможность генерации заглушек без использования API-ключей.
- **Валидация:** Проверка непрерывности ID (`zk1..zkN`), отсутствия дублей, наличия файлов.

### 3. UX и инструменты
- **Веб-интерфейс:** Простая панель управления с отображением статуса, прогресса, логами.
- **Shell-обертки:** Удобные скрипты для CLI (`analyze-script`, `synthesize-tts`, `validate-stage1`).
- **macOS-коннектор:** Возможность использовать `say` из Docker через отдельный сервис.

## Проблемы и риски

### 1. Зависимости и лицензирование
- **catdoc как системная зависимость:** Для `.doc` требуется утилита `catdoc` (ставится через apt в Docker). Риск: локальный запуск вне Docker может падать, если `catdoc` не установлен в ОС.
- **Python-зависимости зафиксированы:** `python-docx` и `google-genai` закреплены версиями в `requirements.txt`, но стоит поддерживать их обновление под контролем (changelog + smoke-тесты).

### 2. Безопасность
- **API-ключи в .env:** Нет шифрования. Риск утечки при коммите.
- **macOS-коннектор:** В примерах используется `http://` и bearer-токен в заголовке. Для удаленного/общего контура нужен TLS (HTTPS, reverse-proxy, VPN/сегментация).

### 3. Надежность
- **LLM-фоллбэк:** Есть fallback не только по `zkN`, но и по абзацам с фильтрацией спикерских/технических блоков. Качество при сложной структуре сценария все равно может деградировать.
- **Ошибки TTS:** Retry c backoff реализован для сетевых провайдеров (`gemini`, `openrouter`), но для `macos`/коннектора выбран fail-fast (без повторов).
- **Валидация WAV:** Проверяется корректность контейнера (заголовок/чтение длительности), но не качество аудио-контента (доля тишины, клиппинг, артефакты).

### 4. Производительность
- **Блокирующие операции:** Нет асинхронности в API. Долгие TTS-запросы блокируют воркер.
- **Память:** При больших сценариях весь текст загружается в память целиком.

### 5. UX
- **Валидация в UI частичная:** Пустой текст фразы проверяется, но для ряда полей (пути/настройки) нет расширенной клиентской валидации до отправки запроса.
- **Прогресс TTS агрегированный:** Есть общий прогресс по количеству файлов, но нет live-прогресса внутри долгой операции (поэлементный статус в реальном времени).

## Рекомендации по улучшению

### 1. Зависимости
- Добавить явный раздел в README про установку `catdoc` для локального запуска (не только Docker).
- Рассмотреть lock-файл зависимостей (`pip-tools`/`requirements-lock.txt`) для воспроизводимых сборок.
- Рассмотреть альтернативы catdoc (например, LibreOffice через `unoconv`).

### 2. Безопасность
- Добавить опциональное шифрование .env (например, через `cryptography`).
- Включить HTTPS для macOS-коннектора по умолчанию.

### 3. Надежность
- Сохранить текущий retry для сетевых провайдеров и добавить опциональный ограниченный retry для macOS-коннектора (например, 1-2 повтора на сетевые ошибки).
- Улучшить валидацию WAV: проверка на тишину, минимальную длительность.
- Расширить fallback для LLM правилами сегментации (аббревиатуры, списки, кавычки/прямая речь) для более стабильной разбивки.

### 4. Производительность
- Перевести API на асинхронность (FastAPI или Flask с gevent).
- Добавить пул воркеров для TTS.
- Реализовать chunking для больших сценариев.

### 5. UX
- Расширить валидацию ввода в UI (обязательные поля, допустимость путей, подсказки до отправки).
- Добавить live-прогресс при генерации TTS (текущий блок/всего, поток логов по шагам).
- Добавить preview текста для каждого блока перед озвучкой.

### 6. Функциональность
- Поддержка нескольких голосов в одном проекте (например, мужской/женский по блокам).
- Экспорт в форматы Premiere (XML, EDL).
- Автоматическое создание промежуточных пауз (silence) между блоками.

## Заключение
Проект **rough_cut_v3** демонстрирует зрелую архитектуру и практичную реализацию Stage 1 для production-пайплайна. Ключевые точки роста: безопасность коннектора в удаленных контурах, более глубокая проверка качества WAV, live-прогресс длинных операций и дальнейшая оптимизация синхронного API-потока.
