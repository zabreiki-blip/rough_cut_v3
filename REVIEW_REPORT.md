# Проверка текущих правок

Дата: 2026-06-09

## Итог

Правки улучшают LLM-анализ, batch dry-run, валидацию поврежденных WAV, изоляцию проектов и часть Stage 2. Все добавленные тесты проходят, но заявлять исправленным весь pipeline Stage 1 → Stage 2 пока нельзя.

Найдены 2 проблемы высокого приоритета, 4 среднего и несколько пробелов в тестах/документации.

## Высокий приоритет

### P1. Stage 2 по-прежнему теряет часть подготовленных блоков

Файлы:

- `src/stage1/analyzer.py:638-652`
- `src/stage2/timeline_parser.py:9-10`

Stage 1 сохраняет raw-сценарий без канонических `ЗКN:`-меток для ручной стратегии. Поэтому рекламируемые форматы `[[VO]]`, `VO:` и `NARRATOR:` дают prepared-блоки, но Stage 2 видит `0` ZK-сегментов.

Также маркеры не вставляются после объединения коротких блоков: объединенный текст отсутствует в исходном raw-тексте как точная строка.

Подтверждено:

```text
[[VO]] / VO: / NARRATOR: -> blocks=1, timeline_zk=0
два коротких LLM-блока после merge -> blocks=1, timeline_zk=0
```

Отдельный случай с одинаковыми блоками создает вложенную метку:

```text
ЗК1: ЗК2: Одинаковый текст...
```

Рекомендация: не восстанавливать Stage 2 через `str.replace`. Формировать канонический raw/timeline из структурированных prepared-блоков либо хранить явное соответствие исходных диапазонов.

### P1. Новый ZK-regex ошибочно распознает текст и загрязняет сегменты

Файл: `src/stage2/timeline_parser.py:10,90-102`

Regex не требует границы после `ЗК`/`ЗАКАДР` и не поглощает поддерживаемые Stage 1 суффиксы.

Подтверждено:

```text
ЗК4.1 Блок...       -> text=".1 Блок..."
ЗК38А + текст       -> text="А Текст..."
ЗАКАДРОВЫЙ текст... -> ошибочно создается ZK-сегмент
```

Текущий тест `test_decimal_suffix_marker_uses_counter` проверяет только ID и не проверяет содержимое сегмента.

Рекомендация: синхронизировать грамматику маркеров с `NARRATOR_MARKER_RE` Stage 1 и добавить отрицательные тесты на обычные слова.

## Средний приоритет

### P2. Fingerprint не учитывает все параметры синтеза

Файл: `src/stage1/gemini_tts.py:154-156,583-598`

Fingerprint учитывает текст, provider, voice, gender и speed, но не учитывает:

- модель Gemini/OpenRouter;
- sample rate;
- `MACOS_TTS_RATE`;
- изменения TTS prompt/реализации.

После изменения этих настроек существующий WAV будет ошибочно пропущен. Также если `ffmpeg` недоступен и tempo не применился, fingerprint все равно сохранит запрошенный speed.

Рекомендация: строить fingerprint из полной нормализованной конфигурации фактически выполненного синтеза.

### P2. Семафор не предотвращает параллельную запись в один проект

Файлы:

- `src/api.py:34-35,221-304`
- `src/stage1/gemini_tts.py:652-655`

Глобальный semaphore разрешает до трех задач одновременно, включая задачи одного проекта. Они могут одновременно записывать один `zkN.wav` и `.meta`.

Smoke-тест подтвердил, что два синтеза с разными voice одновременно дошли до одного output path.

Рекомендация: добавить блокировку на проект/speaker_dir или дедупликацию активной задачи проекта. Запись WAV и meta выполнять атомарно.

### P2. `/stage2/build` возвращает HTML 500 при ошибочном пути

Файл: `src/api.py:683-690`

Новые вызовы `_abs_path()` находятся вне `try/except ValueError`. Путь соседнего проекта теперь вызывает необработанный `ValueError` и HTML 500 вместо JSON 400.

Подтверждено Flask test client:

```text
POST /stage2/build -> status=500, content-type=text/html
```

Рекомендация: перенести разрешение путей внутрь блока обработки `ValueError`.

### P2. Dry-run быстрой фразы все еще перезаписывает WAV

Файл: `src/stage1/gemini_tts.py:747-752`

Batch `synthesize_tts(..., dry_run=True)` теперь сохраняет существующий WAV, но `synthesize_phrase(..., dry_run=True)` по-прежнему безусловно перезаписывает файл с тем же именем.

Подтверждено smoke-тестом для `phrase_preview.wav`.

Рекомендация: применить одинаковую политику dry-run к batch и phrase synthesis.

## Низкий приоритет

### P3. README содержит нерабочий API-пример

Файл: `README.md:183-189`

Пример использует `input/scenario.docx`, но после изоляции проектов API принимает только путь внутри `projects/<project>/`. Проверка вернула JSON 400.

Рекомендация: добавить `project` и путь `projects/<project>/input/scenario.docx`.

### P3. AUDIT_REPORT.md внутренне противоречив

Отчет одновременно помечает проблемы исправленными и оставляет их в списке главных рисков/плане немедленных исправлений. Некоторые заявления о полном исправлении Stage 1 → Stage 2 и ограничения фоновых задач не подтверждаются smoke-проверками.
