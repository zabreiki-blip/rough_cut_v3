# Этап 1: Анализ сценария и подготовка закадровой озвучки

## 1. Цель этапа
Преобразовать исходный сценарий (`.doc`/`.docx`) в набор озвученных файлов для диктора (TTS) с предсказуемыми ID (`zk1`, `zk2`, ...), чтобы дальше автоматически собирать дорожку в Premiere.

## 2. Вход и выход
### Вход
- `input/scenario.doc` или `input/scenario.docx`

### Выход
- `work/scenario_raw.txt` — извлеченный текст из doc/docx.
- `work/scenario_prepared.json` — структурированные блоки закадра.
- `speaker/zk1.wav`, `speaker/zk2.wav`, ... — озвучка по блокам.
- `speaker/manifest.json` — сводный манифест для следующего этапа.

## 3. Структура этапа
1. Конвертация doc/docx в текст.
2. Анализ сценария через OpenRouter (LLM) и разбиение на блоки озвучки.
3. Нормализация текста под TTS.
4. Синтез речи через `gemini-2.5-pro-preview-tts`.
5. Валидация полноты (`zk` без пропусков/дублей) и формирование манифеста.

## 4. Формат блока озвучки
Каждый блок в `scenario_prepared.json`:

```json
{
  "id": "zk1",
  "text_original": "Оригинальный фрагмент сценария",
  "text_for_tts": "Подготовленный текст для озвучки",
  "pause_ms": 300,
  "notes": "Опционально: ударения, темп, оговорки"
}
```

## 5. Правила подготовки текста под TTS
- Один смысловой блок = один `zkN`.
- Короткие, удобные для дикторской начитки фразы.
- Числа, даты, аббревиатуры приводить к произносимому виду.
- Удалять неозвучиваемые ремарки и технические пометки.
- Сохранять последовательную нумерацию без пропусков: `zk1..zkN`.

## 6. Манифест `speaker/manifest.json`
Минимальные поля:

```json
{
  "project": "rough_cut_v3",
  "generated_at": "2026-03-03T00:00:00Z",
  "items": [
    {
      "id": "zk1",
      "file": "speaker/zk1.wav",
      "duration_ms": 0,
      "text_for_tts": "..."
    }
  ]
}
```

## 7. Переменные окружения
- `OPENROUTER_API_KEY` — ключ OpenRouter.
- `GEMINI_API_KEY` — ключ Gemini TTS.

## 8. CLI-команды (план)
1. `analyze-script --in input/scenario.docx --out work/scenario_prepared.json`
2. `synthesize-tts --in work/scenario_prepared.json --out speaker/ --voice <voice_id>`
3. `validate-stage1 --in work/scenario_prepared.json --speaker speaker/`

## 9. Критерии готовности этапа
- Успешно обработан `.doc` или `.docx`.
- Для каждого блока `zkN` создан соответствующий `speaker/zkN.wav`.
- В `speaker/manifest.json` нет пропусков и дублей ID.
- Тексты в `text_for_tts` пригодны к естественной начитке без ручной правки (или список правок зафиксирован в `notes`).

## 10. Риски и контроль
- Ошибки конвертации `.doc` -> использовать fallback (LibreOffice/textutil/pandoc).
- Длинные блоки ухудшают TTS -> вводить лимит длины блока и автоделение.
- Несовпадение ID в сценарии и озвучке -> обязательная проверка непрерывной последовательности.
