# Этап 2: Сборка секвенции в Premiere Pro

## 1. Цель этапа
Собрать черновую секвенцию (rough cut) в Premiere Pro, объединив закадровую озвучку (Stage 1), синхроны спикеров и стендапы ведущего в правильном порядке по сценарию.

## 2. Общий workflow

```
Монтажёр (Premiere)                CEP-плагин                  Python API
───────────────────                ──────────                  ──────────
1. Синхронизирует спикера       2. "Зарегистрировать"       3. Сохраняет в БД:
   (мультикам + звук)              → POST /speakers            имя, длительность,
   на отдельном таймлайне                                      путь к секвенции

4. Размечает сценарий (docx):
   СНХ Анпилогов → seq:anpilogov_01

5. Загружает сценарий            6. "Построить таймлайн"     7. Полный парсинг →
   через веб-UI                     → GET /timeline             упорядоченные сегменты

8. "Собрать секвенцию"          9. Создаёт секвенцию
   в CEP-плагине                   через ExtendScript:
                                   V1: видео спикеров/ведущего
                                   A1: звук спикеров/ведущего
                                   A2: закадр (TTS WAV)
```

## 3. Типы сегментов сценария

| Тип | ID-префикс | Источник в Premiere | Как определяется |
|-----|-----------|---------------------|-----------------|
| ЗК (закадр) | `zk1`, `zk2`... | WAV из Stage 1 | highlight + не bold |
| СНХ (синхрон) | `snh1`, `snh2`... | Секвенция спикера (зарег. в базе) | bold + `СНХ` + имя |
| ВЕДУЩИЙ | `ved1`, `ved2`... | Секвенция ведущего (зарег. в базе) | bold + `ВЕДУЩИЙ` |
| ТЕХ (отбивка и пр.) | `tech1`... | Плейсхолдер / цветная плашка | `ОТБИВКА`, `ШАПКА`, caps |

## 4. Формат разметки спикеров в сценарии

Монтажёр добавляет ссылку на секвенцию Premiere рядом с меткой СНХ:

```
СНХ Алексей Анпилогов → seq:anpilogov_ice_01
[03:50] (…) по плану нужно было инженерному корпусу...

ВЕДУЩИЙ-2 → seq:vedushiy_planshet_01
В апреле 2024 года над Гренландией совершал полёт...
```

Формат ссылки: `→ seq:<имя_секвенции>`
- Имя секвенции совпадает с именем таймлайна в Premiere
- Парсер извлекает имя и ищет в базе зарегистрированных спикеров

## 5. Подготовка спикеров в Premiere

### Варианты съёмки
- 1 камера со звуком
- 2 камеры со звуком (мультикам)
- 1-2 камеры + отдельная запись звука

### Процесс
1. Монтажёр создаёт мультикам-секвенцию (или обычную) в Premiere
2. Синхронизирует камеры и звук
3. Делает грубую нарезку нужных фрагментов
4. Называет секвенцию осмысленным именем: `anpilogov_ice_01`
5. Нажимает "Зарегистрировать" в CEP-плагине

### Что регистрируется
```json
{
  "name": "anpilogov_ice_01",
  "speaker": "Алексей Анпилогов",
  "duration_sec": 45.2,
  "sequence_id": "...",
  "project_path": "/path/to/project.prproj",
  "registered_at": "2026-03-07T..."
}
```

## 6. Полный парсинг сценария (Stage 2 analyzer)

Расширение Stage 1 парсера. Вместо только ЗК-блоков — ВСЕ сегменты по порядку.

### Вход
- `work/scenario_prepared.json` (Stage 1, только ЗК)
- Исходный `.docx` (все абзацы с форматированием)

### Выход — `work/full_timeline.json`
```json
{

  "segments": [
    {
      "index": 1,
      "type": "zk",

      "wav_file": "speaker/zk1.wav",

    {
      "index": 2,

      "id": "ved1",

      "sequence_ref": "vedushiy_karta_01",
      "duration_ms": null
    },
    {
      "index": 3,
      "type": "snh",
      "id": "snh1",
      "speaker": "Алексей Анпилогов",
      "text": "до сих пор есть особые соглашения...",
      "sequence_ref": "anpilogov_ice_01",
      "timecode_approx": "01:32",
      "duration_ms": null
    },
    {
      "index": 4,
      "type": "zk",
      "id": "zk2",
      "text": "Причём, заявление министра обороны...",
      "wav_file": "speaker/zk2.wav",
      "duration_ms": 6200
    },
    {
      "index": 5,
      "type": "tech",
      "id": "tech1",
      "text": "ОТБИВКА. НАЗВАНИЕ ПРОГРАММЫ",

```

Длительности `snh` и `vedushiy` берутся из базы зарегистрированных спикеров.
Длительности `tech` — дефолт (3 сек) или настраиваемый.
Таймкоды приблизительные, используются как подсказка, не для точной нарезки.

## 7. CEP-плагин для Premiere

### Технологии
- CEP (Common Extensibility Platform) панель
- HTML/CSS/JS — UI плагина
- ExtendScript — управление Premiere (создание секвенций, импорт, нарезка)
- HTTP-запросы к Python API

### UI плагина (панель в Premiere)
```
┌─────────────────────────────────────┐
│  ROUGH CUT v3                       │
├─────────────────────────────────────┤
│  Проект: [greenland_ep01      ▼]   │
│                                     │
│  ── Спикеры ──────────────────────  │
│  [Зарегистрировать текущую секв.]   │
│                                     │
│  anpilogov_ice_01    ✓ 45.2s       │
│  shalandin_green_01  ✓ 38.1s       │
│  vedushiy_karta_01   ✓ 22.0s       │
│  vinnik_green_01     ✗ не найден   │
│                                     │
│  ── Сборка ───────────────────────  │
│  Сегментов: 47 (ЗК:28 СНХ:12 В:5) │
│  Готовность: 89% (5 не привязаны)  │
│                                     │
│  [Собрать секвенцию]                │
│  [Обновить статус]                  │
├─────────────────────────────────────┤
│  Лог: Секвенция создана, 47 клипов │
└─────────────────────────────────────┘
```

### Функции ExtendScript
1. **Регистрация спикера** — получить имя и длительность активной секвенции
2. **Импорт WAV** — импортировать все `zk*.wav` в bin "ЗК"
3. **Сборка секвенции** — создать новую секвенцию, расставить клипы:
   - V1: вложенные секвенции спикеров/ведущего
   - A1: звук спикеров/ведущего (из их секвенций)
   - A2: WAV-файлы закадра
   - V2: цветные плашки для tech-сегментов (slug/color matte)
4. **Маркеры** — поставить маркеры с текстом на каждый сегмент

## 8. Python API — новые эндпоинты

### База спикеров
```
POST   /api/speakers                — зарегистрировать спикера
GET    /api/speakers?project=X      — список спикеров проекта
DELETE /api/speakers/<name>         — удалить спикера
```

### Полный таймлайн
```
POST   /api/timeline/build          — парсинг docx → full_timeline.json
GET    /api/timeline?project=X      — получить таймлайн
GET    /api/timeline/status?project=X — статус готовности (% привязанных)
```

### Хранение
- `projects/<name>/work/full_timeline.json` — полный таймлайн
- `projects/<name>/work/speakers.json` — база спикеров проекта

## 10. Порядок реализации

### Фаза 1: Бэкенд (Python)
1. `stage2/models.py` — модели Segment, Speaker
2. `stage2/timeline_parser.py` — полный парсинг docx → сегменты всех типов
3. `stage2/speaker_db.py` — JSON-хранилище спикеров
4. Новые API-эндпоинты в `api.py`
5. Тест на реальном сценарии

### Фаза 2: CEP-плагин (основа)
6. Структура CEP, manifest.xml
7. UI панели (HTML/CSS/JS)
8. Регистрация спикеров (ExtendScript ↔ API)
9. Импорт WAV-файлов закадра

### Фаза 3: Сборка секвенции
10. ExtendScript: создание секвенции + расстановка клипов
11. Маркеры с текстом сегментов
12. Обработка отсутствующих спикеров (плейсхолдеры)

### Фаза 4: UI в браузере
13. Страница Stage 2 в веб-интерфейсе (таймлайн, статус привязки)
14. Ручной маппинг спикеров через UI (fallback если CEP недоступен)

## 11. Критерии готовности
- Все ЗК-блоки из Stage 1 на аудиодорожке в правильном порядке
- Зарегистрированные спикеры вставлены как nested sequences
- Незарегистрированные спикеры отмечены плейсхолдерами (цветной slug + маркер)
- Маркеры на таймлайне с текстом каждого сегмента
- Порядок сегментов соответствует сценарию

## 12. Ограничения и допущения
- Таймкоды в сценарии приблизительные — используются только как подсказка в маркерах
- Спикеры синхронизируются вручную до начала сборки
- Длительность tech-сегментов (отбивки) — фиксированная (настраиваемая)
- Ведущий обрабатывается так же, как спикер (отдельная секвенция)
- Один проект = один сценарий = одна финальная секвенция
