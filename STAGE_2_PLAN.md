# Stage 2.1 — автоматическая привязка СНХ к Premiere

## Цель

Продолжить текущий Rough Cut v3 без отдельного проекта: использовать уже
синхронизированные Premiere-секвенции (две камеры и отдельный звук), найти в них
реплики из подтверждённого сценария и автоматически заменить плейсхолдеры
точными nested sequence ranges.

Сторонние таймкоды считаются приблизительной подсказкой. Источником точных
границ служат word timestamps локального Whisper.

## Рабочий поток

1. Монтажёр синхронизирует камеры и отдельный звук в исходных секвенциях.
2. CEP-панель регистрирует активную секвенцию по стабильному Premiere
   `sequenceID` и `projectItem.nodeId`.
3. Панель экспортирует полный guide WAV через Adobe Media Encoder.
4. Backend транскрибирует только новый/изменившийся guide, а модель и уже
   готовые word indexes переиспользует.
5. Matcher ищет нормализованную реплику:
   - сначала в окне около стороннего таймкода;
   - затем по полному интервью;
   - с русской нормализацией, fuzzy score и альтернативами.
6. Уверенные совпадения получают `auto_matched`; спорные проверяются в веб-UI:
   можно прослушать диапазон, выбрать альтернативу и поправить in/out.
7. `full_timeline.json` получает фактические source ranges и длительности.
8. CEP перед batch conform повторно инспектирует активную целевую секвенцию,
   проверяет проект и target ID, затем вставляет только `auto_matched` и
   `confirmed` ranges.
9. На целевой sequence сохраняются маркеры `RC_SYNC` с block UID, текстом,
   source range и confidence.

Исходные sync-секвенции не изменяются. Batch conform разрешён только на
отдельной активной Rough Cut секвенции; первый прогон обязателен на её копии.

## Артефакты

Все данные продолжают жить внутри текущего проекта:

```text
projects/<project>/
  work/
    scenario_normalized.json
    sync_sources.json
    sync_matches.json
    full_timeline.json
    sync_audio/<source_id>.wav
    transcripts/<source_id>.words.json
```

`scenario_normalized.json` — редакционный источник истины. Sync-артефакты
регенерируемы и не меняют канонический текст сценария.

## Реализованный API

```text
GET|POST|DELETE /stage2/sync-sources
GET|PUT           /stage2/sync-sources/<source_id>/audio
PUT               /stage2/sync-sources/<source_id>/words
POST              /stage2/sync-jobs/start
GET               /stage2/sync-jobs/<job_id>
GET|PATCH         /stage2/sync-matches
PATCH             /stage2/sync-matches/<block_uid>
POST              /stage2/build
GET               /stage2/timeline
```

`source_ids` в sync job означает «принудительно транскрибировать эти
источники». Сопоставление всегда использует все уже готовые word indexes, чтобы
последовательный экспорт A → B не стирал результаты A.

Одна Premiere sequence может содержать одного, нескольких или всех спикеров.
`speaker` остаётся основным legacy-именем, `speakers` хранит дополнительные
имена, а `all_speakers=true` делает source доступным для любой реплики.

## Статусы

- `auto_matched` — сильное однозначное совпадение около ожидаемого таймкода;
- `needs_review` — fallback, неоднозначность или средняя уверенность;
- `confirmed` — диапазон принят редактором;
- `not_found` — допустимого диапазона не найдено.

Нулевые ranges, timestamps вне длительности секвенции и stale-результаты от
предыдущей revision нормализации не допускаются в сборку.

## Защита и fallback

- Backend закрыт API token; CEP CORS включается явно только для local file
  origin.
- Source ID нельзя незаметно перепривязать к другой Premiere sequence.
- При смене активного источника CEP очищает форму и поднимает существующую
  регистрацию с backend.
- Batch останавливается на первой непроверенной ошибке placement.
- FCP7 XML остаётся fallback, если CEP/ExtendScript недоступен.

## Критерии готовности

- Guide одного источника транскрибируется один раз, модель переиспользуется.
- Нет зависимости от точного совпадения каждого слова Whisper.
- Все спорные ranges можно прослушать и поправить до conform.
- Несколько источников участвуют в одном общем поисковом пуле.
- Фактическая длительность СНХ двигает последующие блоки таймлайна.
- Batch изменяет только проверенную активную target sequence и оставляет
  редакционные маркеры.
- Runtime-пилот в Premiere подтверждает nested/multicam A/V placement на одном
  диапазоне, затем на копии полной Rough Cut.

## Следующее улучшение после пилота

По нескольким уверенным совпадениям оценивать устойчивый offset/drift сторонних
таймкодов для каждой секвенции и автоматически сдвигать поисковое окно. Это
ускорит поиск в расшифровках, где внешний таймер систематически отличается от
таймлайна Premiere, но не должно блокировать текущий fuzzy full-transcript
fallback.
